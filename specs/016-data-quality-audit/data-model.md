# Data Model: Controlled Data Quality Audit Pipeline

## Training Row Record

Represents one source row from the project’s training label file.

**Fields**

- `image_id`
- `target`
- `bottle_type`
- `source_split`

**Validation Rules**

- Every source training row must appear exactly once in the master audit table.
- `image_id` is the row identity used to join prediction evidence, Spec 014 evidence, image-quality evidence, and duplicate evidence.
- `target` must preserve the project’s binary contract: `0 = Reusable`, `1 = Not Reusable`.

## Prediction Evidence Record

Represents row-level model evidence used to rank label quality and boundary uncertainty.

**Fields**

- `image_id`
- `prediction_source`
- `v2b_probability`
- `v2b_prediction`
- `v2b_correct`
- `v2b_confidence`
- `v2b_loss_or_risk_score`
- `decision_boundary_distance`
- `oof_probability`
- `oof_prediction`
- `oof_correct`
- `oof_confidence`
- `oof_loss_or_risk_score`
- `label_quality_reliability`

**Validation Rules**

- V2B prediction evidence is optional but must be merged when present.
- OOF prediction evidence is preferred when present and must be consumed as a precomputed input rather than generated by this feature.
- If OOF evidence is absent, `label_quality_reliability` must explicitly indicate limited evidence.
- Prediction evidence must not be derived from test labels or leaderboard feedback.

## Spec 014 Governance Evidence Record

Represents previously reviewed hard-row decisions from Spec 014.

**Fields**

- `image_id`
- `hard_row_status`
- `hard_example_type`
- `spec014_final_failure_mode`
- `spec014_recommended_action`
- `spec014_phase3_use_allowed`
- `blocked_reason`

**Validation Rules**

- Allowed hard-row evidence and blocked-row evidence must both be traceable to saved Spec 014 outputs.
- Blocked-row evidence is stricter than any later supportive heuristic or score.
- Suspected mislabeled blocked rows are always unsafe for training in this feature.

## Image Quality Evidence Record

Represents availability and crop-quality evidence for a training image.

**Fields**

- `image_id`
- `roi_quality_flag`
- `crop_quality_score`
- `annotation_evidence_flag`
- `image_width`
- `image_height`
- `image_mean_brightness`
- `image_contrast`
- `edge_strength`
- `background_heavy_score`

**Validation Rules**

- Missing or unreadable images must be identified explicitly.
- ROI/crop problems must remain visible as named evidence rather than being hidden only inside a generic score.
- Image-quality evidence must not modify source labels.

## Duplicate Evidence Record

Represents exact or near-duplicate grouping and label-conflict evidence.

**Fields**

- `image_id`
- `duplicate_group_id`
- `near_duplicate_score`
- `duplicate_conflict_flag`

**Validation Rules**

- Exact duplicate groups must be reproducible from deterministic file-level evidence.
- Duplicate groups with conflicting labels must always be excluded from the cleaned training manifest until later review.
- Near-duplicate evidence may be partial or unavailable without invalidating the full audit.

## Data Quality Master Row

Represents the full merged row in `data_quality_master.csv`.

**Fields**

- all fields from the Training Row Record
- all fields from the Prediction Evidence Record
- all fields from the Spec 014 Governance Evidence Record
- all fields from the Image Quality Evidence Record
- all fields from the Duplicate Evidence Record
- `cluster_id`
- `anomaly_score`
- `label_issue_score`
- `manual_review_status`
- `data_quality_bucket`
- `exclude_from_training`
- `exclusion_reason`
- `review_priority`
- `evidence_summary`
- `audit_run_id`
- `created_at`
- `source_config_hash`

**Validation Rules**

- The master table must contain exactly one row per source training row.
- Every bucket decision must be explainable from row-level evidence.
- The master table must include traceability fields sufficient to identify the audit run and configuration source.

## Data Quality Bucket

Represents the controlled final status assigned to a row.

**Allowed Values**

- `clean_train`
- `hard_valid_train`
- `exclude_from_training`
- `manual_review_required`

**Validation Rules**

- `clean_train` rows have no blocking or unresolved risk evidence.
- `hard_valid_train` rows are allowed hard rows that remain training-safe after audit checks.
- `exclude_from_training` rows are directly unsafe and cannot be used in training.
- `manual_review_required` rows remain excluded from `cleaned_training_manifest.csv` in this feature.

## Cleaned Training Manifest Row

Represents one row included in the future training-safe manifest.

**Fields**

- `image_id`
- `target`
- `data_quality_bucket`
- `hard_training_allowed`
- `exclude_from_training`
- `exclusion_reason`
- `review_priority`
- `evidence_summary`

**Validation Rules**

- Only `clean_train` and `hard_valid_train` rows may appear in the cleaned training manifest.
- No `manual_review_required` row may appear in the cleaned training manifest during this feature.
- The manifest must remain empty rather than unsafe if no row qualifies.

## Manual Review Template Row

Represents a reviewer-facing row for later human decisions.

**Fields**

- `image_id`
- `current_bucket`
- `review_priority`
- `label_issue_score`
- `blocked_reason`
- `roi_quality_flag`
- `duplicate_conflict_flag`
- `evidence_summary`
- `proposed_review_action`
- `reviewer_notes`

**Validation Rules**

- The template records future human decisions but does not modify source labels in this feature.
- Rows in the review template are not automatically approved for training.

## Audit Summary Report

Represents the run-level output package describing audit coverage and safety.

**Fields**

- `total_rows`
- `clean_train_count`
- `hard_valid_train_count`
- `exclude_from_training_count`
- `manual_review_required_count`
- `warnings`
- `oof_prediction_status`
- `label_quality_reliability`
- `no_training_started`
- `no_submission_created`
- `no_test_labels_used`
- `no_leaderboard_tuning`

**Validation Rules**

- Summary counts must reconcile with the bucket outputs.
- Safety booleans must remain true for every Spec 016 run.
- Reliability status must reflect whether OOF and optional evidence were actually available.
